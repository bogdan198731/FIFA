# World Cup Prediction Game

A web app where users predict World Cup match outcomes and compete on a
leaderboard. This repository is being built in incremental phases.

**Stack**

- Frontend — Angular 18 (standalone components, signals)
- Backend — Java 17 + Spring Boot 3
- Database — PostgreSQL
- ORM — Spring Data JPA / Hibernate
- Auth — JWT (added in a later phase)

---

## Phase 1 — Project Foundation

This phase establishes the technical base of the application. It delivers:

- An Angular frontend project with a `core / shared / features / layout`
  module layout.
- A Spring Boot backend project with package skeletons for `auth`, `user`,
  `match`, `prediction`, `question`, `leaderboard`, `admin`, and `common`.
- PostgreSQL connectivity via Spring Data JPA.
- A working CORS configuration so the Angular dev server can call the API.
- Environment-based configuration on both sides (`environment.ts` /
  `application-{profile}.yml`).
- A `/api/health` endpoint that the frontend calls on startup to confirm the
  full stack is wired.

---

## Phase 2 — Database Models

This phase defines the persistent core of the application.

- JPA entities: `User`, `Match`, `Prediction`, `TournamentQuestion`,
  `TournamentAnswer`.
- Spring Data repositories for each entity (e.g. `UserRepository`,
  `MatchRepository`, …).
- Enums: `Role` (USER / ADMIN), `MatchType` (REGULAR / KNOCKOUT),
  `MatchStage` (GROUP / ROUND_OF_16 / QUARTER_FINAL / SEMI_FINAL /
  THIRD_PLACE / FINAL).
- Schema is owned by **Flyway** — see
  [backend/src/main/resources/db/migration](backend/src/main/resources/db/migration).
  JPA is configured with `ddl-auto: validate`, so the entities must match the
  migrations.
- `V2__seed_data.sql` seeds three users (one admin), six matches, and three
  tournament questions so the rest of the app has something to render.

## Phase 3 — Authentication

JWT-based auth with BCrypt password hashing and role-based access control.

**Backend**

- `POST /api/auth/register` — creates a USER, returns `{token, expiresInMs, user}`.
- `POST /api/auth/login` — verifies credentials, returns the same envelope.
- `GET  /api/auth/me` — returns the current user; requires `Authorization: Bearer <token>`.
- Spring Security with a stateless session policy.
  [`SecurityConfig`](backend/src/main/java/com/example/worldcup/auth/SecurityConfig.java)
  permits `/api/health` and `/api/auth/{register,login}`, restricts
  `/api/admin/**` to `ROLE_ADMIN`, and authenticates everything else under
  `/api/**`.
- HS256 JWTs generated by
  [`JwtService`](backend/src/main/java/com/example/worldcup/auth/JwtService.java)
  with subject = username and a `role` claim. Secret and expiration are
  controlled by `JWT_SECRET` / `JWT_EXPIRATION_MS`.
- A dev-only
  [`DevUserSeeder`](backend/src/main/java/com/example/worldcup/auth/DevUserSeeder.java)
  rewrites the seed users' placeholder hashes on startup so `admin`, `alice`,
  and `bob` can sign in with the password `password` in the `dev` profile.
- Validation errors and `ApiException`s are normalised by
  [`GlobalExceptionHandler`](backend/src/main/java/com/example/worldcup/common/GlobalExceptionHandler.java).

**Frontend**

- Routes: `/login`, `/register`, `/dashboard`, `/profile`. Dashboard and
  profile sit behind [`authGuard`](frontend/src/app/core/guards/auth.guard.ts);
  login and register sit behind `guestGuard` (logged-in users get bounced to
  the dashboard).
- [`AuthService`](frontend/src/app/core/services/auth.service.ts) holds the
  current user as a signal, persists the JWT in `localStorage`, and exposes
  `login` / `register` / `logout` / `bootstrap`. `bootstrap` runs once at app
  start via `APP_INITIALIZER` and rehydrates the user via `/auth/me`.
- [`authInterceptor`](frontend/src/app/core/interceptors/auth.interceptor.ts)
  attaches the `Authorization` header to every request and signs the user out
  on a `401` response.
- A simple header layout
  ([`HeaderComponent`](frontend/src/app/layout/header/header.component.ts))
  switches between sign-in / register links and a username + sign-out button.

Migrations run automatically on backend startup. To re-seed a clean DB:

```sql
DROP SCHEMA public CASCADE;
CREATE SCHEMA public;
```

then start the backend again — Flyway will rebuild from V1.

## 1. Database setup

Create a local PostgreSQL database and user that match the defaults in
[backend/.env.example](backend/.env.example):

```sql
CREATE USER worldcup WITH PASSWORD 'worldcup';
CREATE DATABASE worldcup OWNER worldcup;
GRANT ALL PRIVILEGES ON DATABASE worldcup TO worldcup;
```

You can override any of these via environment variables (see
[backend/src/main/resources/application.yml](backend/src/main/resources/application.yml)):

- `DB_URL` — JDBC URL (default `jdbc:postgresql://localhost:5432/worldcup`)
- `DB_USERNAME`
- `DB_PASSWORD`
- `JPA_DDL_AUTO` — `validate` (Flyway owns the schema)
- `SPRING_PROFILES_ACTIVE` — `dev` (default) or `prod`
- `CORS_ALLOWED_ORIGINS` — comma-separated, default `http://localhost:4200`
- `JWT_SECRET` — HMAC signing key (≥32 bytes). Override in any non-dev environment.
- `JWT_EXPIRATION_MS` — token lifetime, default 24h

## 2. Backend — run locally

```bash
cd backend
mvn spring-boot:run
```

The app starts on `http://localhost:8080`. Verify with:

```bash
curl http://localhost:8080/api/health
# {"status":"UP","service":"worldcup-backend","timestamp":"..."}
```

The Spring Actuator endpoint `http://localhost:8080/actuator/health` is also
exposed.

### Build / test commands

```bash
mvn compile          # compile only
mvn test             # run tests
mvn spring-boot:run  # start the API
mvn package          # produce target/worldcup-0.0.1-SNAPSHOT.jar
```

---

## 3. Frontend — run locally

```bash
cd frontend
npm install   # first time only
npm start     # ng serve on http://localhost:4200
```

Open `http://localhost:4200`. The page displays a **Backend health** card; if
the API is reachable it shows `UP — worldcup-backend` along with the server
timestamp. If the backend is down it shows `DOWN — <error>`.

The API base URL is configured in
[frontend/src/environments/environment.ts](frontend/src/environments/environment.ts).

### Build / test commands

```bash
npm start            # ng serve
npm run build        # production build → dist/frontend
npm test             # karma + jasmine unit tests
```

### Try it locally

After running the backend and frontend (see sections 2 and 3 above):

1. Visit `http://localhost:4200/register` and create an account, or sign in at
   `/login` as `admin`/`alice`/`bob` with the password `password` (dev only).
2. After auth you land on `/dashboard`. The backend health card still works
   here, now reached as an authenticated user.
3. `/profile` displays your account and a sign-out button. Signing out clears
   the JWT and bounces you back to `/login`.
